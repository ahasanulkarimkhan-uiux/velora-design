# Design decisions

## From a featured look to individual pieces

The editorial entry introduces the collection before the product grids. New Arrivals and Selected Essentials present names, categories and illustrative prices in a repeatable pattern. This is a rationale for comparison, not a measured improvement in shopping behavior.

## Keep the price separate from the name

The earlier isolated Figma stress check found a long garment name running into the price. The revision reserves a price slot, lets the name wrap in the remaining space and places the category below. The subsequent mockup review records a two-line name with a separate price.

The evidence is an isolated Figma render. It does not prove that every repeated card has been corrected or that arbitrary content, zoom and browser resizing work. The selected story panel explains this decision rather than demonstrating a rendered product card.

## Two browsing routes

The Tailoring Edit provides a collection entry, while New Arrivals and Selected Essentials support browsing individual pieces. The structure diagram presents those routes. It is not a clickable prototype or a complete journey through product detail and checkout.

## Preserve the existing scope

The substantiated composition is a 1280 px desktop Figma storefront. Earlier wording suggesting mobile responsiveness is unsupported by the documented frame inventory. This package adds no design or implementation and makes no responsive implementation claim.

## Presentation and verification limits

The latest local final-review copy identifies publication-set panels 00–05 as the photo-free sequence. Older photo-led hero, tailoring, product and showcase exports retain unresolved asset rights. This package uses the cover, decision panel and structure diagram without alteration. It sacrifices detailed UI imagery to avoid publishing uncleared photography.

Runtime keyboard behavior, links, email signup validation, pending and confirmation states, broader contrast checks and repeated-card stress coverage remain unverified here. Publishing documentation does not resolve those design and implementation questions. No user research, testing, client work or commercial outcomes are inferred from this concept.
